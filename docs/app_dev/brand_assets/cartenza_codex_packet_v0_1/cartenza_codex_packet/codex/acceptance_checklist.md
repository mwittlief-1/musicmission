# Cartenza Visual Implementation Acceptance Checklist

## Branding replacement

- [ ] User-facing prototype references use `Cartenza` rather than `Waymark`, except in migration/internal notes.
- [ ] Product vocabulary remains intact: Survey, Mission, Route, Listen, Signal, Atlas, Landmark, Region, Frontier, Dead End, Waypoint, Compass.
- [ ] Tagline appears as `Your music. Mapped.` or approved alternate.

## Visual direction

- [ ] Primary mark follows Concept 5: circular cartographic C / compass-seal direction.
- [ ] Secondary textures borrow from Concept 1: topographic contour / taste-terrain language.
- [ ] Visual treatment remains Night Vision: dark, restrained, premium, intelligent, modern.
- [ ] No generic map pin, bright waveform equalizer, loud neon gradient, or childish exploration motif.

## App surfaces

- [ ] Welcome/onboarding screen uses Cartenza lockup and Night Vision palette.
- [ ] Starter Atlas/profile surface uses dark card styling and restrained map texture.
- [ ] Mission cards use concise route/hypothesis styling without overloading the UI.
- [ ] Listen/player surface remains uncluttered; logo/texture is minimal or absent during playback.

## Tokens

- [ ] Colors are sourced from `tokens/cartenza_night_vision_tokens.json` or equivalent constants.
- [ ] Gold accent is used sparingly for signal/guide/selection.
- [ ] Teal accent is used sparingly for Atlas/system/frontier/substrate.
- [ ] Text contrast is readable on device.

## Assets

- [ ] SVG starter assets compile/render correctly.
- [ ] App icon placeholder works at small sizes.
- [ ] No generated concept-board screenshots are embedded as production UI.
- [ ] Assets are organized so final designer-provided vectors can replace the placeholders later.

## Product integrity

- [ ] Visual changes do not alter mission schema, survey evidence, atlas digest, or playback behavior.
- [ ] Branding is isolated in theme/assets/constants where possible.
- [ ] App remains compatible with Alpha v0 scope and Option B Supabase backend plan.
